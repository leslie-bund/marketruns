# Core integration for hybrid identity

1. After ParticipantDO and the core profile save succeed, call identity `POST /auth/enrollment-proof` over `x-identity-internal`. Use `verified` in production; `preverified` is allowed only with explicit `EDGE_ENV=staging` or local `ALLOW_HEADER_AUTH=true`. Pending/failed KYC gets no proof or session.
2. Return the opaque `enrollmentProof` in `participant.recorded` alongside the same participant and selected role. Never derive it on mobile and never log it. Reject duplicate participant ids and any session/identity role mismatch.
3. Keep the existing `/auth/*` proxy generic. It must forward POST, GET, and PATCH plus `Authorization`; do not add public enrollment-proof or biometrics-service routes. The proxy injects `x-identity-internal` into `/auth/face/enroll`, which also requires that credential at the identity worker.
4. Onboarding carries only the document, email, and consent—not a selfie or R2 reference. Mobile sends fresh face frames directly through `/auth/face/enroll`. Do not log, persist, trace, or send capture bodies to analytics or public media storage. Forward them over TLS and enforce the agreed body cap (8 MB per image, 96 MB per request maximum). Ordinary handoff evidence keeps its existing authorized capture path.
5. Preserve `preverified` as visibly distinct from `verified`; production `canTransact` accepts only `verified`. Biometric KYC completion upgrades identity-owned KYC state, then calls server-only edge `POST /internal/identity/kyc` with the shared identity token and `EDGE_URL`. The edge updates ParticipantDO and the durable core profile without changing role, document, or markets.
6. Core reconciliation is idempotent and completes before the identity job can pass or issue a session. If the edge call fails, the job remains pending and its promoted capture is retained; a later signed callback or poll retries without another selfie. Never return a successful job while the core profile is still `preverified` or `pending`.
7. Mobile expects `enrollmentProof` from eligible onboarding and forwards BVN/NIN type+number to hybrid enrollment. Production still requires the pre-existing verified KYC gate and real Smile ID completion for verified status.
